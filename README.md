# VoiceToText

Telegram-бот на Python 3.11 / aiogram 3.13.1:
- голосовые сообщения расшифровываются через прежний посегментный генератор;
- видеокружки получают встроенные синхронизированные ASS-субтитры и возвращаются через `sendVideoNote`.

## Как работают кружки

1. Бот скачивает MP4 во временную уникальную директорию.
2. FFprobe проверяет видео, длительность и наличие звука.
3. FFmpeg быстро извлекает моно OGG/Opus 16 кГц / 24 кбит/с.
4. `whisper-large-v3` получает `verbose_json` с таймингами `segment` и `word`.
5. Короткие реплики создаются по реальным меткам первого/последнего слова. Время внутри речи не интерполируется. Строки ограничены по ширине кружка.
6. FFmpeg/libass встраивает белые субтитры с аккуратной обводкой. Для скорости квадратный кадр не масштабируется повторно, звук сохраняется в AAC.
7. Результат отправляется именно `sendVideoNote`. Если Telegram отклоняет кружок, бот явно сообщает об этом и отправляет обычное видео.

Штатный квадратный кадр не обрезается и не растягивается. Для нестандартного неквадратного источника используется размытый фон, а весь исходный кадр сохраняется. FFmpeg запускается через `asyncio.to_thread`, не блокируя event loop. Тяжёлые обработки ограничены семафором. Временная директория удаляется после успеха или ошибки.

Если звука/речи нет, возвращается исходный кружок без пустых субтитров.

## Локальный запуск

```bash
python3.11 -m venv .venv
. .venv/bin/activate             # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # укажите BOT_TOKEN и GROQ_API_KEY
# Debian/Ubuntu:
sudo apt-get update && sudo apt-get install ffmpeg fonts-dejavu-core
python main.py
```

Проверьте кодировщики/фильтры:

```bash
ffmpeg -hide_banner -encoders | grep libx264
ffmpeg -hide_banner -filters | grep subtitles
```

## Docker / Render

```bash
docker build -t voice-to-text .
docker run --rm --env-file .env -p 8080:8080 voice-to-text
```

В Dockerfile уже установлены FFmpeg и DejaVu Sans. На Render задайте переменные окружения из `.env.example`; `PORT` обычно выставляет Render. Сервис использует polling и HTTP healthcheck `GET /` для UptimeRobot. Не включайте webhook одновременно с polling.

Для голосовых и видео по умолчанию используется точная `whisper-large-v3`. Голосовые до 30 секунд распознаются целиком одним запросом, более длинные — фрагментами по 30 секунд с сохранением контекста. Это уменьшает ошибки на стыках и число запросов по сравнению с прежней нарезкой каждые 5 секунд. Модель получает инструкцию по русской пунктуации, а результат дополнительно нормализуется без замены распознанных слов. Если кастомный endpoint не возвращает `words`, применяются его настоящие сегменты с дополнительным ограничением ширины; выдуманные тайминги не создаются.

### Ускорение

По умолчанию: `VIDEO_PRESET=ultrafast`, `VIDEO_THREADS=2`, `VIDEO_CRF=23`, аудио для Groq 24 кбит/с. Квадратное видео не проходит лишнее масштабирование. Это существенно сокращает локальное кодирование по сравнению с `medium`, но итоговое время также зависит от CPU Render, очереди, загрузки/выгрузки Telegram и ответа Groq. На слабом CPU установите `MAX_CONCURRENT_VIDEOS=1`: одиночная задача получит больше ресурсов.

## Переменные окружения

Обязательные: `BOT_TOKEN`, `GROQ_API_KEY`.

Необязательные (значения по умолчанию):

| Переменная | По умолчанию |
|---|---:|
| `PORT` | `8080` |
| `MAX_CONCURRENT_VIDEOS` | `2` |
| `MAX_VIDEO_SECONDS` | `60` |
| `MAX_VIDEO_FILE_MB` | `20` |
| `WHISPER_MODEL` | `whisper-large-v3` |
| `CHUNK_SECONDS` | `30` |
| `GROQ_TIMEOUT_SECONDS` | `90` |
| `GROQ_RETRIES` | `3` |
| `FFMPEG_TIMEOUT_SECONDS` | `180` |
| `VIDEO_CRF` | `23` |
| `VIDEO_PRESET` | `ultrafast` |
| `VIDEO_THREADS` | `2` |
| `VIDEO_WHISPER_MODEL` | `whisper-large-v3` |
| `SUBTITLE_FONT` | `DejaVu Sans` |
| `SUBTITLE_FONT_SCALE` | `0.046` |
| `SUBTITLE_MAX_CHARS_PER_LINE` | `20` |

Если старые значения заданы в Render Environment, новые значения по умолчанию их не перекроют: удалите `VIDEO_PRESET`, `SUBTITLE_FONT_SCALE` и `SUBTITLE_MAX_CHARS_PER_LINE` или обновите их вручную.

## Тесты и необходимая интеграционная проверка

```bash
python -m unittest discover -s tests -v
```

Тесты не требуют сетевых ключей и проверяют кириллицу, перенос строк, паузы, границы ASS и валидацию ответа Groq.

Перед production необходимо отдельно провести реальные проверки с Telegram/Groq/FFmpeg: короткий и длинный кружок, речь с паузами, длинная фраза, отсутствие речи, сохранение звука, два одновременных запроса. Юнит-тесты не заменяют эти проверки.
